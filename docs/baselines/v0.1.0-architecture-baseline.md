## Purpose

This baseline freezes the repository architecture and declared lifecycle state before the evidence-lineage, privacy, distribution, activation-ledger, and scientific golden-bundle work begins.

It is an architectural baseline. It is not evidence that external scientific software was installed or executed, and it is not a scientific acceptance record.

The machine-readable companion is:

- `docs/baselines/v0.1.0-architecture-baseline.json`

## Frozen scope

- 26 source-backed Skills
- 7 `active` Skills
- 19 `development` Skills
- 0 planned Skill identities
- 4 active calculation-code integrations: QE, VASP, CP2K, and SIESTA
- 19 planned software identities

The seven active Skill source-tree SHA-256 values are copied from `registry/skill-registry.yaml` into the machine-readable baseline. The baseline also records Git blob anchors for the principal registries, validation workflow, repository policy, and validation tools.

## Evidence boundary

The baseline supports only the following statement:

> At source commit `33dc893ad7dee6cdab8d645f7e25ff44f345c899`, the repository declared the recorded architecture, lifecycle counts, active Skill source-tree hashes, validation commands, and known blockers.

It does not support the following statements:

- that QE, VASP, CP2K, SIESTA, or any development software is installed in the current environment;
- that every declared task has been validated against native software execution;
- that an `active` Skill is scientifically sufficient for every task;
- that repository tests establish numerical convergence or physical validity;
- that cross-record evidence lineage is already complete.

git diff --check -- . ':(exclude)skills/qe-rigorous-calculations/references/official-*'

The QE `official-*` exception preserves generated official mirror text and must remain manifest-validated.

## Blockers carried forward

1. A shared bundle semantic validator must enforce record references, byte hashes, DAG order, state compatibility, code/task/structure identity, and claim ceilings.
2. Repository-wide privacy and restricted-content scanning must cover credentials, private paths, hosts, scheduler accounts, POTCAR content, large scientific artifacts, and Git history.
3. Development Skill behavior tests must enter offline CI without becoming routable.
4. An active-only distribution must provide a physical boundary for third-party runtimes.
5. Every active lifecycle entry must retain an immutable activation evidence record.
6. One legally reusable two-dimensional QE phonon-EPC-Tc golden bundle must close the scientific workflow path.
