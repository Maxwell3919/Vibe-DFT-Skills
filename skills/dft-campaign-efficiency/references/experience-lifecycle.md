# Experience lifecycle

1. Preserve a free-form case narrative and its minimal evidence kernel.
2. Reconstruct actual stage state and label missing evidence.
3. Normalize only the stable meaning into an immutable campaign record.
4. Deduplicate by record id and source-manifest or evidence checksum.
5. Classify comparability, state gates, and evidence completeness.
6. Create a positive speed/accuracy candidate only from repeated accepted evidence; create failure-avoidance candidates with an explicitly narrower claim.
7. Mark `validated-for-this-campaign` for one protocol/campaign scope.
8. Promote to `cross-campaign-validated` only after independent comparable campaigns support the claimed scope.
9. Attach counterexamples, falsifiers, and version/architecture applicability.
10. Mark `superseded` rather than deleting a contradicted rule.
11. Revalidate recommendations after calculation-code, compiler, library, scheduler, hardware, filesystem, or scientific-protocol changes.

If no safe rule emerges, record `No new transferable experience`; this is a valid outcome.
