# Comparability and evidence

Records are directly comparable only when code, code version, task type, anonymized system class, atom count, and scientific protocol id match. The protocol must bind the scientific objective, model, convergence criteria, and accuracy acceptance. For multistage workflows, also match the stage role and parent-artifact lineage.

Configuration ids may differ only in the efficiency choice being studied. If multiple numerical or model choices differ, classify the comparison as confounded and propose a controlled pilot.

Use only scientifically accepted records for positive speed/accuracy recommendations. Failed or rejected records remain valuable for bounded failure avoidance, observability, and preflight design, but cannot prove a faster accepted route.

Compare the same state gate. Do not compare an executable-finished record with an artifact-complete record, or a numerically valid intermediate with a scientifically accepted observable.

Curve-valued evidence must share an overlap domain and a declared comparison rule. A selected point, directory label, or finite scalar is not a substitute for curve convergence.

Require at least two accepted observations for each compared configuration. Prefer medians, report sample counts and both core-hours and wall time, and retain contrary observations.

For a counterfactual schedule or reuse estimate, report the cost model and call the result `estimated`. Promote it to measured evidence only after a controlled execution or a validated trace replay.
