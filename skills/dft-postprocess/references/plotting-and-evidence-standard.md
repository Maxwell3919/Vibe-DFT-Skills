# Plotting and evidence standard

- Plot only finite, validated structured columns.
- Preserve original values; transformations must create new columns or explicit metadata.
- State units, normalization, zero/reference, broadening, interpolation, smoothing, aggregation, and uncertainty.
- Use readable labels and a restrained, consistent style. Do not encode scientific status only by color.
- Save a machine-readable plot metadata JSON with input hash, columns, labels, limits, style, output hash, and command.
- Validate output existence and nonzero size. For important figures, render and inspect visually.
- Never use smoothing or axis limits to hide discontinuities, imaginary modes, missing data, or failed ranges.
- A visual trend is a hypothesis until a script-backed numerical statistic supports it.
- After visual QA, embed every completed figure in the user response from its absolute local path and show the exact source-data route used to produce it.
- Display the associated numerical result table or summary alongside the figure. Do not substitute a plot for source provenance or numerical validation.
- For a combined bands-DOS figure, render typed TDOS and at least one typed PDOS channel together. Keep TDOS visually dominant, preserve it under PDOS filtering, and record selected/excluded channels and styles in plot metadata.
- When caller-verified high-symmetry labels are available, validate their coordinates against sampled band k-points, store them in normalized band metadata, and reuse that hash-bound metadata for individual and combined bands-DOS ticks/guides. Never infer Γ/X/M names from unlabeled numeric QE coordinates alone.
- Adapt the reusable band style from validated normalized data rather than material-specific plotting scripts: deep-red primary bands, neutral gray projected-band background, dashed zero/reference and high-symmetry guides, inward ticks, exact horizontal endpoints, and deterministic channel colors.
- For multiple band datasets, render one labeled axes per dataset. Preserve each dataset's own path extent and reference metadata; a shared vertical window is a presentation setting, not proof that structures, paths, functionals, spin treatments, or reference energies are comparable.
- For multiple projection selectors, make separated panels the primary figure. Preserve both supported encodings: `bubble` maps marker area linearly to weight as `marker_area_pt2 = marker_scale^2 * projection_weight`; `line-width` uses `line_width_pt = marker_scale * 0.45 * projection_weight` with no colored base width at zero weight. Use a light neutral background band, translucent bubble faces, and visible same-channel outlines. Put the declared background-bands label and every caller-provided or selector-derived species/orbital label in the relevant legends and metadata. An optional plain-plus-overlap overview may be produced, but its metadata must warn that overlap can obscure individual contributions. Require exact k-index, path-coordinate, band-index, and energy alignment between every bands/fatband table.
- For VASPKIT text tables, require a finite caller-supplied additive energy offset and a nonempty reference description. Never assume that VASPKIT's zero is the desired SCF, NSCF, VBM, vacuum, or other reference.
- For structure top/side views, record ASE version, source hash, boundary-site expansion, display radii/colors, view definition, and connectivity mode. Covalent-radius or explicit-distance connections are graphical rules only; do not interpret them as bond orders.
- For a real-space field section, record the crystallographic plane `(hkl)`, plane offset, periodic interpolation, in-plane basis/origin, sampling resolution, atom inclusion tolerance, crop window, colormap, and displayed value range. A crop or saturated color range is a presentation choice, not evidence that excluded space or values are unimportant.
- Use `turbo` with limits 0–1 for caller-declared ELF unless explicitly overridden. Use a symmetric zero-centered diverging map for caller-declared charge-density differences. Never infer the physical field kind from its numeric range.
- Structure-plus-isosurface figures must record the external renderer, project format, isovalue and unit, positive/negative convention, opacity, scale, rotation, and output dimensions. Do not embed material-specific arrows, claims, or panel assembly in the reusable renderer.
